# 共用樂理抽離驗證

日期：2026-10-27（Asia/Taipei）。本機修改完成，未由本次工作提交、推送或發布網站。

## 實作範圍

- 唯一來源：`packages/music-core/core.js`，版本 1.0.0。
- 發布副本：`dist/music-core.js` 與另一個產品的 `Seiren/music-core.js`，內容完全一致。
- 兩邊的 `music.js` 改為使用明確的相容設定；保留原 export 名稱、生成／approach、鋼琴配置、吉他按法、MIDI 與其他模組轉出。
- 抽出的項目：音級與音程、和弦種類／延伸音解析、和弦組成音、音名拼字，以及 Khimaira 原有的移調／羅馬級數。
- 同步工具、版本 checksum、固定輸出回歸、瀏覽器驗證，以及兩個專案的 AGENTS 維護指引已加入。

此次沒有統一兩個產品的生成策略、旋律保護、演奏音型、專案格式、弱起、拍號或 MIDI 行為。`Bdim.minor`、接受的別名及 `spellChord` 等差異以相容設定保留。

## 其他開發與既有測試差異

Seiren 舊 QA 的兩項失敗在任何修改前就存在：

1. `alpha6-arranger.test.js` 要求所有風格保留同一條固定根音骨架；目前 Mandopop 的專屬和聲策略已有不同結果。
2. `beta-20261026.test.js` 曾允許旋律下方 B3 對 C5 的小九度；現行 `harmony.js` 已拒絕這種衝突，現行 harness 也明確驗證拒絕。沒有為了舊測試撤銷這項修正。

Khimaira 工作區在本次執行期間持續出現其他和聲教材、範例、演奏、UI 與外掛修改。最後凍結副本的三項失敗為：

1. `example-pool.test.js`：各風格方向／範例數量預期。
2. `example-titles.test.js`：Japanese rock 的氣氛標題預期。
3. `exploration.test.js`：低變化時保留原根音的預期。

將同一份凍結程式只換回原 `music.js`，三項仍以同樣方式失敗；再將本次抽離單獨套到穩定提交，98 項全部通過。因此沒有把這些其他工作的問題當成本次抽離修正，也沒有重設或覆蓋它們。這份報告不宣稱整個持續變動的工作區已全部通過測試。

## 重跑與後續維護

完整操作和需求分流規則見 [共用樂理維護](../../packages/music-core/README.md)。本次測試輸出、原始輸出 fingerprint 與瀏覽器結果在 [evidence](evidence/)。

共用核心更新後需同步兩邊並驗證。產品專屬需求保留在各自的策略層。若要更改相容規則，先檢查具體輸出差異與已 debug 案例，再更新測試；不要直接覆蓋另一個產品的同名函式。
